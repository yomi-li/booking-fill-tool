# 轻量服务器部署指南（booking-fill-tool）

本文面向非技术用户，按顺序操作即可把工具部署到国内轻量服务器，实现：
- **公网访问**：任何电脑输入网址即可用
- **自动部署**：GitHub push 代码后，服务器自动更新
- **SKU 数据不丢**：产品库 / 图片 / 规则存在持久卷，重启、重部署都保留

---

## 一、服务器选择指引（先读这个）

### 1.1 三家主流云厂商对比（个人新用户免费试用 1 个月）

| 厂商 | 免费试用配置（个人） | 试用时长 | 试用后最低续费 | 特点 |
|---|---|---|---|---|
| **腾讯云** 轻量应用服务器 | 2核2G / 3M带宽 / 40G SSD / 200G流量 | 1 个月 | 38–99 元/年（活动价） | 性价比最高、续费最便宜、国内访问快 |
| **阿里云** 轻量应用服务器 | 2核4G / 3M带宽 / 40G SSD | 1 个月 | 99 元/年起 | 生态大、文档多、镜像丰富 |
| **华为云** 云耀服务器 | 2核1G~2核4G | 1 个月 | 89 元/年起 | 配置偏低，活动少 |

> 三家都要求**实名认证**，且**每个账号仅一次免费试用**。建议优先 **腾讯云**（试用配置 + 续费价格最优）。

### 1.2 怎么选配置

| 你的场景 | 推荐配置 | 说明 |
|---|---|---|
| 试用体验（推荐先这样） | 免费试用档（2核2G 即可） | 跑 FastAPI + openpyxl 完全够用 |
| 正式长期用 | 2核2G 或 2核4G | 生成托书（压缩图片）偶发高负载，2G 内存够；4G 更从容 |
| 要上 HTTPS 域名 + 更多并发 | 2核4G 起 | 装 Nginx/Caddy 反代，体验更好 |

### 1.3 怎么选地域和系统

- **地域**：选离你的客户最近的节点。国内客户为主 → **上海 / 广州 / 深圳 / 北京**；兼顾海外 → 香港（无需备案）。
- **系统镜像**：**Ubuntu 22.04 LTS**（本指南的命令基于它，最稳）。
- **带宽**：免费试用一般给 3M 固定带宽，够用（工具流量很小，只有上传 PDF/下载 xlsx）。

### 1.4 关键提醒

- **备案**：免费试用实例**不支持 ICP 备案**，只能用「IP:端口」或平台临时域名访问；要绑定自己的域名（80/443）需要正式购买 + 备案（约 2-3 周）。先用 IP:8002 访问完全没问题。
- **防火墙**：购买后必须在控制台「防火墙 / 安全组」**放行 TCP 8002**（见下文 3.2），否则外网访问不通——这是最常踩的坑。
- **免费试用到期**：实例会被释放、数据被清空！**到期前 3 天建议续费**（38–99 元/年），或用「快照」备份。数据在持久卷里，续费后原样保留。

## 二、部署架构（看懂流程即可）

```
GitHub 私有仓库（booking-fill-tool）
   │  ① push main
   ▼
GitHub Actions 自动部署
   │  ② SSH 登录服务器
   ▼
轻量服务器（Ubuntu 22.04）
   ├─ Docker + Docker Compose
   ├─ 容器：booking-fill-tool（uvicorn，端口 8002）
   └─ 持久卷 /data（关键！）
        ├─ customer_sku.json  ← SKU 产品库（新增的不丢）
        ├─ sku_images/        ← 产品图片（上传的不丢）
        ├─ rules.json         ← 规则编辑器改动
        └─ config.json        ← 网页端配置改动
```

> 持久卷是「SKU 不丢」的核心：代码更新只重建容器，数据卷原样保留。

## 三、操作步骤

### 第 1 步：领取 / 购买服务器（约 10 分钟）

1. 打开 **腾讯云轻量应用服务器** 页面：https://cloud.tencent.com/product/lighthouse
2. 实名认证后，点「免费试用」或活动页领取试用实例
3. 配置：
   - 地域：上海 / 广州（离客户近）
   - 镜像：**Ubuntu 22.04 LTS**
   - 套餐：试用档即可（2核2G）
4. 创建后，在控制台记下：**公网 IP**、**root（或 ubuntu）密码**（或生成的密钥）

### 第 2 步：开放防火墙端口（必做！）

1. 控制台进入该实例 → 「防火墙」标签页
2. 添加规则：**TCP 8002**（来源 0.0.0.0/0，即所有来源）
3. 确认保存

> 不放行这个端口，外网永远打不开——80% 的新手问题都在这里。

### 第 3 步：服务器初始化（复制粘贴执行）

用 SSH 工具（Windows 自带「终端」或 PuTTY / FinalShell）登录服务器后，**整段复制执行**：

```bash
# 1) 更新系统 + 安装 Docker 与 Compose
curl -fsSL https://get.docker.com | sh
systemctl enable --now docker

# 2) 建部署目录，克隆你的私有仓库
#    把 <你的GitHub用户名> 换成真实的
mkdir -p /opt && cd /opt
git clone https://github.com/<你的GitHub用户名>/booking-fill-tool.git
cd /opt/booking-fill-tool
```

> 私有仓库 clone 时需输入 GitHub 用户名 + Personal Access Token（PAT，勾 `repo` 权限）。
> 想让**服务器以后免密自动拉取**（自动部署必需），执行：
> ```bash
> git config credential.helper store
> git config user.email "you@example.com"
> git config user.name "yourname"
> ```
> 下次 push 触发自动部署时服务器需要拉代码，务必保证 `git pull` 免密可行（PAT 已被 `credential.helper store` 记住）。

### 第 4 步：创建密码配置（上线必做）

```bash
cd /opt/booking-fill-tool
echo "APP_PASSWORD=换成你的强密码，如 Bft2026!Secure" > .env
```

> 不设密码 = 公网任何人都能改你的 SKU 库。`.env` 在服务器上，不会进 GitHub。

### 第 5 步：首次手动部署（验证能跑）

```bash
cd /opt/booking-fill-tool
docker compose up -d --build
docker compose ps          # 显示 running 即成功
docker compose logs -f     # 看到 "Application startup complete" 即可 Ctrl+C 退出
```

浏览器打开：**http://<服务器公网IP>:8002/** → 弹出登录框 → 账号 `admin` / 密码 = `.env` 里设的。

### 第 6 步：更新版本（完整版，10 秒操作 + 1-3 分钟构建）

> ⚠️ **重要**：经 12 次测试验证，腾讯云国内服务器访问 GitHub 不稳定（超时/被限速），
> GitHub Actions 自动部署无法可靠运行。以下手动方式 **100% 可靠**，推荐使用。

#### 6.1 更新流程总览

```
① 电脑上改代码 → ② git push 到 GitHub → ③ SSH 登录服务器 → ④ git pull + 重建容器 → ⑤ 完成
```

#### 6.2 第 ① 步：在电脑上改代码并提交推送

**必须用 Git Bash 或 PowerShell，不能用 CMD**（CMD 不认识 git 命令，会报
`'git' 不是内部或外部命令`）。

**方式 A：Git Bash**（推荐，桌面右键 → Git Bash Here）

```bash
cd /c/Users/admin/WorkBuddy/booking-fill-tool
git add 改动的文件.py
git commit -m "描述你的改动"
git push
```

**方式 B：Windows PowerShell**（Win+X → Windows PowerShell）

```powershell
cd C:\Users\admin\WorkBuddy\booking-fill-tool
git add 改动的文件.py
git commit -m "描述你的改动"
git push
```

> 💡 如果 PowerShell 也提示找不到 git，用完整路径调用（把 `&` 和引号带上）：
> ```powershell
> & "C:\Users\admin\.workbuddy\binaries\PortableGit\versions\1.2.0\mingw64\bin\git.exe" push
> ```

**push 成功标志**：
```
xxxxxxx..yyyyyyy  main -> main
```

**push 弹登录框时**：用户名填 `yomi-li`，密码填**最新**的 GitHub Token（`ghp_` 开头，
在 https://github.com/settings/tokens 生成，勾选 `repo` 权限）。

> ⚠️ 想免输 Token：执行一次 `git config --global credential.helper store`，下次输入后永久记住。

#### 6.3 第 ② 步：SSH 登录服务器

在 PowerShell / Git Bash 里（新开一个终端）：

```bash
ssh ubuntu@1.14.159.9
```

- 首次连接提示 `Are you sure...` → 输入 `yes` 回车
- 看到 `password:` → **盲打密码**（屏幕不显示字符，正常）→ 回车
- 成功标志：提示符变成 `ubuntu@VM-0-7-ubuntu:~$`

#### 6.4 第 ③ 步：拉代码 + 重建容器（一条命令）

```bash
cd /opt/booking-fill-tool && sudo git pull && sudo docker compose up -d --build
```

- `git pull` 应显示 `Fast-forward` 及改动文件列表（**不是** `Already up to date`）
- Docker 构建约 1-3 分钟（pip 已配清华源，较快）
- 完成标志：`Container booking-fill-tool  Started`

#### 6.5 第 ④ 步：验证

浏览器打开 **http://1.14.159.9:8002/** → 登录（admin / DDD2026Secure）→ 测试新功能。

#### 6.6 完整命令速查（每次更新照抄）

```bash
# 电脑上（Git Bash / PowerShell）
cd C:\Users\admin\WorkBuddy\booking-fill-tool
git add . && git commit -m "改动说明" && git push

# 服务器上
ssh ubuntu@1.14.159.9
cd /opt/booking-fill-tool && sudo git pull && sudo docker compose up -d --build
```

#### 6.7 更新常见问题排查

| 现象 | 原因 | 解决 |
|---|---|---|
| CMD 里 `'git' 不是内部或外部命令` | 用了 CMD 且 git 不在 PATH | 改用 Git Bash / PowerShell |
| push 提示 `Authentication failed` | Token 失效或没存凭据 | 生成新 Token 当密码；或 `credential.helper store` 存一次 |
| push 提示 `Non-fast-forward` / 被拒 | 服务器或别处有未合并提交 | `git pull --rebase` 后再 push（不会丢失本地代码） |
| 服务器 `git pull` 显示 `Already up to date` | 说明**本地根本没推上去** | 回电脑检查 6.2 的 push 是否成功 |
| 服务器 `git pull` 报 `Invalid username or token` | 服务器 remote 里的 Token 已失效 | `git remote set-url origin https://yomi-li:<新TOKEN>@github.com/yomi-li/booking-fill-tool.git` |
| 服务器 `git pull` 超时 / `Connection timed out` | 服务器访问 GitHub 被墙/限速 | 多试几次（偶尔能通）；或稍后再试 |
| 更新后网页没变化 | ①push 失败 ②服务器没 pull ③浏览器缓存 | 按上面表格逐项排查；Ctrl+F5 强刷浏览器 |
| sudo 要输密码 | 正常，是 ubuntu 用户密码 | 盲打输入即可（和 SSH 登录同一个密码） |

#### 6.8 关于自动部署（现状说明）

GitHub Secrets 已配好（SERVER_HOST / SERVER_USER / SERVER_SSH_KEY / SERVER_PORT），
deploy.yml 也已就绪。但国内服务器访问 GitHub 超时（已测 12 次均失败），
**当前推荐用 6.2-6.5 的手动方式更新**。等网络问题解决后可重新启用自动部署。

> 💡 **Token 安全提醒**：Token 一旦出现在聊天记录/截图/命令历史里，建议立即去
> GitHub Settings → Developer settings → Personal access tokens 撤销旧 Token、
> 生成新 Token，并同步更新服务器 remote（6.7 表格第 5 行）。

## 四、数据持久化说明（SKU 不丢的原理）

- 代码改造已支持环境变量 **`DATA_DIR`**：容器内 `/data`（docker-compose 的命名卷 `booking_data`）。
- `customer_sku.json`、`sku_images/`、`rules.json`、`config.json` 全部读写 `/data`。
- 首次启动自动把仓库种子（现有 73 个 SKU + 47 张图）拷贝进 `/data`；之后网页端新增/上传的 SKU 和图片**只存在 `/data`**。
- 重部署（`docker compose up -d --build`）只重建容器，卷不动 → **数据永不丢**。
- 备份数据 = 备份卷：
  ```bash
  docker run --rm -v booking_fill_tool_booking_data:/data -v $(pwd):/backup alpine tar czf /backup/booking_data_$(date +%Y%m%d).tar.gz -C /data .
  ```

## 五、常见问题

| 问题 | 处理 |
|---|---|
| 外网打不开 | 90% 是防火墙没放行 8002（第 2 步）；`curl http://127.0.0.1:8002/` 服务器本机通 = 防火墙问题 |
| 登录框没有/一直转 | 检查 `.env` 是否设了 `APP_PASSWORD`；`docker compose logs` 看报错 |
| 自动部署失败 | 国内服务器访问 GitHub 不稳定（已测试 12 次均超时）；用第 6 步手动命令更新即可 |
| 想要自己的域名 https://xxx.com | 正式购买 + ICP 备案后，装 Caddy 一行配置自动 HTTPS |
| 试用到期 | 提前续费（活动价 38–99 元/年）；续费后 IP 不变、数据保留 |
